amd64 开发机与 NVIDIA Jetson Orin NX aarch64 均完成原生 Release 构建。
测试时 Jetson 既有传感器/飞控进程保持运行，规划基准在 localhost 隔离域运行，不消费或发布飞行指令。

### 历史功能与检测

| 验证项 | 结果 |
| --- | --- |
| 两平台原生构建 | 通过，只有两个功能包 |
| 12 项 C++ 核心回归 | 两平台全部通过 |

C++ 用例覆盖直达、非零三轴速度及高于原高度上限的轨迹、竖杆绕行、空/坏/超容量地图、
非法参数/状态、起终点碰撞与旧路径失效、同起终点、节点数/时间预算、horizon 与动态时间索引、
双树保留和淘汰、封闭墙、原语端点之间的障碍。
独立几何检查用原始点而非 `isSafe()` 当真值；每段另取 1,001 个时间点复核距离、p/v 连续性和动力学边界。

ROS2 回归覆盖等待输入、目标规划、child-frame 三轴速度旋转、目标阻挡、错误 frame、
断流过期、恢复、空点云、缺少 z 字段、重复时标不刷新地图、非法负时标、目标版本变化与失败空轨迹。
此处空轨迹指 PlanResult；当前 Path 是最后成功预览，失败时不发布空 Path。
`colcon test-result` 统计为 **15 tests / 0 failures**，其中含两个 CTest 包装项；
逻辑用例是 12 个 C++ 测试与 1 个包含多场景的 ROS2 进程测试，不能当成 15 个独立场景。

### 历史性能与边界

历史基准为 10 Hz 输入和规划、80 ms 搜索预算、4 m 目标、贯穿高度范围的竖杆。
当时 benchmark 未加载安装 YAML；当前默认加载 YAML 的 300 ms 配置，以下数字不代表当前 launch。
统计排除开始 1 秒；结果间隔是客户端接收间隔，包含规划、调度、DDS 与客户端开销。
`planning_ms` 只覆盖搜索，不包括建图/序列化。

amd64 最终 30 秒记录：290 次结果，288 次到达目标轨迹，2 次 TIMEOUT。
搜索 P50/P95/P99/max = 44.78/55.40/73.50/80.81 ms；
结果间隔 P95/P99/max = 110.97/121.67/142.10 ms。
规划进程约 0.395 CPU 核，RSS 55.84→56.05 MiB，地图最多 402 点。

Jetson 最终 120 秒记录：1,190 次结果，1,189 次到达目标轨迹，1 次 TIMEOUT，无 STALE_INPUT。
搜索 P50/P95/P99/max = 69.19/71.49/72.61/80.17 ms；
结果间隔 P95/P99/max = 111.87/135.32/141.08 ms。
规划进程约 0.685 CPU 核，RSS 约 56 MiB，地图最多 402 点。

**不能据此宣称稳定满足全链 P99≤100 ms，也没有完成 30 分钟热稳态、SITL 跟踪或实飞验收。**
超预算返回失败，不通过加大时间预算、降低碰撞精度或忽略失败来统计成功率。

首轮基准保留完整 ROS 轨迹消息，累积的大量 Python 对象导致测试端垃圾回收停顿，
Jetson 出现最长约 969 ms 的结果接收间隔和 11 次输入过期；改为只保留统计摘要后重新测量。
这是测试工具修复，不是删除或掩盖规划失败；最终统计仍保留所有 TIMEOUT/STALE_INPUT。

### 历史真实数据回放

2026-09-23 被动录制 16.899 s、78.3 MiB ROS2 SQLite bag：160 帧点云、6,228 条里程计、
27 条飞控状态。27 条状态均为 `armed=false`；未执行任何解锁或起飞。
点云每帧 29,830～30,003 点，中位数 29,920.5，header 间隔中位数 97.474 ms。
点云和里程计均为 `odom`，源时钟约 2,840 s，是设备时间，不能与主机 Unix 时间直接相减。

在 `stamp_clock=receive` 下保留原始坐标/时标，使用第一条里程计加 `(1,0,0) m` 为离线目标。
最近原始障碍点距起点 **0.10427 m**，小于默认有效半径约 **0.64821 m**。
因此两平台各得到 150 次 `NO_PATH`，bag 播完后 30 次 `STALE_INPUT`，全部为空轨迹。
这是“真实输入能接入且正确拒绝”的证据，**不是 Odin 实景避障成功的证据**。
未修改点云、删除近身点、缩小机体半径或伪造起点高度以制造成功。

Jetson 回放地图峰值 34,488 点，RSS 峰值约 62.28 MiB，约 0.155 CPU 核。
回放拒绝路径的搜索耗时很短，不代表同点数成功绕障的搜索性能。
原始记录只保存在采集者本地，不随公开仓库分发。

上游 README 的 Google Drive bag 链接本次返回 HTTP 404；没有验证上游 ROS1 bag，
也没有声称复现论文的动态障碍或细杆飞行结果。

### 历史修复过程中保留的失败

1. 恢复 shot 动力学拒绝后，原启发式连接时间过短，首轮动态近目标用例失败，
   简单搜索耗时约 0.5～0.7 s。使用相同多项式有限时长重试后回归通过，未放宽速度/加速度限制。
2. 首轮 ROS2 测试在消息包尚未安装完成时启动，导入 `path_planning.msg` 失败；
   完成安装并 source 后，两平台真实进程测试通过。
3. ASan 初次运行在 PCL 分配/Eigen 释放边界报告越界。Eigen 在定义 `__SANITIZE_ADDRESS__` 时
   改用手工对齐，而 Ubuntu 系统 PCL 用 glibc 16 字节对齐 malloc。检测构建显式统一此 ABI 后通过；
   保留 ASan、UBSan 和泄漏检测，未添加错误忽略列表。
4. 基准隔离域初值 233 超出 Fast DDS 默认端口映射范围，改为 230；自动测试使用 232。
5. 非实时平台仍有搜索超时和输出间隔超标，按实测报告；本次不更改操作系统实时调度策略。
